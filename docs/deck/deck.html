EcoTrace
02

Every battery tool tells you what is draining you.

None of them tell you why — and "why" is the only part that is expensive to get wrong, because the fix is usually not where the symptom is.

MainActivity.onCreate()            the alarm nobody questioned
  -> AlarmManager.setRepeating()      wakes the device every 15 min, no backoff
    -> SyncService.onStartCommand()   96 triggers a day
      -> UserRepository.sync()        no cache hit, goes to network
        -> NetworkManager.fetch()     no timeout set
          -> wakeLock.acquire()     <-- the line the report points at

The acquire() is a symptom. The setRepeating() is the cause, and it is three files and four hops upstream. Patching the symptom moves the number and leaves the chain intact.

EcoTrace
10

A CI check, not a developer tool.

Nobody budgets for a lint tool. Teams budget for store ratings, one-star reviews and battery complaints in support — all of which are downstream of exactly these defects.

Today

Desktop app, $29 per developer seat. Self-hostable. The report is the deliverable: it is what gets attached to the ticket and read by someone who will not install anything.

Next

A pull-request action that fails the build on a new critical finding and comments the traced chain on the diff. This is the wedge: it moves the cost from review time to before merge.

Then

Fleet mode — the same rules over a portfolio of apps, ranked by energy debt, with the grade as the metric engineering leadership already reports on.

Why it scales: the 23 rules are a static corpus, so marginal cost per additional repository is a clone and a walk. The ADB layer is the part that does not generalise — and that is deliberate, because it is a diagnostic for the developer, not the product.
